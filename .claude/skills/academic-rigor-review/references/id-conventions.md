# 统一 ID 与引用规则

为了让多个 Subagent 的产物可被下游任务消费，所有 P 任务必须使用以下统一 ID 规则。

## ID 类型

| 对象 | ID 规则 | 用途 |
| --- | --- | --- |
| 核心主张 | `C-001` | 在所有任务中追踪同一主张 |
| 证据 | `E-001` | 追踪原始来源或实验结果 |
| 缺陷 | `D-001` | 追踪问题、修复和关闭状态 |
| 验证任务 | `V-001` | 追踪补充实验、核查和验收 |
| 评价维度 | `DIM-01` 至 `DIM-08` | 统一八个评价维度 |

## 八个评价维度（用于 DIM 编号）

| ID | 维度 |
| --- | --- |
| `DIM-01` | 理论基础 |
| `DIM-02` | 文献与相关工作 |
| `DIM-03` | 论证与推理 |
| `DIM-04` | 研究方法 |
| `DIM-05` | 证据与数据 |
| `DIM-06` | 有效性与偏差控制 |
| `DIM-07` | 可复现性与可证伪性 |
| `DIM-08` | 结论边界与研究贡献 |

## 引用规则

1. **任何 claim 必须有 `C-NNN` ID**，P1 分配，后续 P 任务只引用不重建。
2. **任何 evidence 必须有 `E-NNN` ID**，由 P2 或 P3 分配，关联到具体来源。
3. **任何 defect 必须有 `D-NNN` ID**，由发现该 defect 的 P 任务分配，关联 `C-NNN`。
4. **任何 verification task 必须有 `V-NNN` ID**，由 P4/P5 提出，P7 跟踪关闭状态。
5. **任何 P6 的评分必须关联 `DIM-NN`**，并附评分锚点。

## 版本追踪

每个 artifact 必须记录：

- `article_version`：被评价文章的版本（如 `v1`, `v2`）
- `protocol_version`：评价协议版本（如 `1.0`）
- `task_status`：`pending` / `in_progress` / `completed` / `superseded`
- `open_items`：未完成事项清单

## 反例：反模式

- ❌ 在 P3 中重新定义 C-002 主张（应引用 P1 已分配的 ID）
- ❌ D-005 没有关联任何 C-NNN（缺陷无法追溯到具体主张）
- ❌ P6 直接给"8 维平均 4.0"（无评分锚点，等同于平均掩盖否决性缺陷）
- ❌ P7 修改主张后未触发 P3/P5 重跑
