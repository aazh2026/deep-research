# paper.md 模板

每篇 `paper.md` 必须严格遵循以下结构。顺序、字段名、加粗规则均不可改动，便于后续批量解析与对比。

## 完整模板

```markdown
# <Title>

## 基本信息

- **论文标题**：<Title>
- **作者**：<Authors>
- **发表年份**：<Year>
- **venue**：<Venue>
- **arXiv/DOI**：<arXiv:XXXX.XXXXX | DOI:10.xxxx/...>
- **提交日期**：<YYYY-MM-DD>（<latest revision>）
- **分类**：<arXiv categories, comma-separated>
- **原文链接**：<canonical URL>
- **项目页**：<project page URL, optional>

## 核心价值

<来自原表的「核心价值」字段，1–3 句话点出这篇工作在评测体系中的独特定位>

## 关键贡献

<来自原表的「关键贡献」字段，分要点列出数据集规模、任务设计、方法亮点>

- 数据规模：...
- 任务设计：...
- 方法亮点：...

## 摘要

<原文 abstract，英文原文，不翻译不省略>

## 价值指标

<来自原表的「价值指标」字段，关键数字必须用 `**bold**` 包裹>

- 数据规模：**N 篇论文 / M 文档 / K 问**
- 主指标：**ANLS**、**F1**、**Acc**
- 关键成绩：模型 **XX%**，人类 **ZZ%**

## 整理备注

- **整理来源**：<source file path>
- **类别**：<原表所属章节>
- **应用场景**：<原表「应用场景」字段>
- **fetch_status**：<success | partial | failed>
- **fetch_source**：<arxiv | acl | doi | fallback>
```

## 字段填写规则

### 基本信息

| 字段 | 必填 | 规则 |
|---|---|---|
| 论文标题 | ✅ | 去掉 HTML 标签；保留原大小写 |
| 作者 | ✅ | 用逗号 + 半角空格分隔；超过 6 人可写「前 3 作者 et al.」+ 全列表在摘要前 |
| 发表年份 | ✅ | 优先 venue 年份，缺则用 arXiv 首次提交年 |
| venue | ✅ | 缩写：WACV / ACL / NeurIPS / arXiv 等 |
| arXiv/DOI | ✅ | 二选一；都无则写 `（无）` |
| 提交日期 | ⭕ | 格式 `YYYY-MM-DD`；括号内可附「vN: YYYY-MM-DD」 |
| 分类 | ⭕ | arXiv 主分类 + 次要分类，逗号分隔 |
| 原文链接 | ✅ | 必须能直接打开；优先 arxiv abs 形式 |
| 项目页 | ⭕ | GitHub / HF / 官方主页 |

### 核心价值

- 长度：1–3 句话
- 视角：从「评测体系中的定位」出发，不是从「论文做了什么」出发
- 必须保留原表的措辞，除非有 HTML 标签污染

### 关键贡献

- 长度：4–8 个项目符号
- 必须保留具体数字（规模、成绩、参数量）
- 关键术语可加粗：`MHST`、`ColPali`、`Hi-VT5`

### 摘要

- 必须是英文 abstract 原文
- 不要翻译、不要省略、不要「摘要如下」之类的引导句
- 如果原文 abstract 分多段，保留段落分隔

### 价值指标

- 关键数字必须 `**bold**`
- 指标名称加粗：`**ANLS**`、`**F1**`、`**Recall@k**`
- 表格形式的指标可保留原表结构（但优先级低于列表）

### 整理备注

- `整理来源`：源文档相对路径，便于追溯
- `类别`：原表所属章节（综述 / 单页 / 图表 / 多页 / RAG / 评测）
- `应用场景`：原表的「应用场景」字段，无则填 `通用`
- `fetch_status`：
  - `success` — 抓取到 abstract + 元数据
  - `partial` — 只抓取到部分字段（如 abstract 但无 categories）
  - `failed` — 完全抓取失败，仅靠原表数据
- `fetch_source`：实际抓取的来源类型

## 反模式

❌ 在 `基本信息` 中混入论文内容（视频正在解说……）
❌ 把摘要翻译成中文
❌ 在「关键贡献」中写「综上所述，这篇论文……」（这是摘要的事）
❌ 在「价值指标」中省略数字（如「模型表现良好」→ 必须写「模型 41.5 EM」）
❌ 用 `TBD`、`待补充` 之类的占位符（除非确实无法获取）
❌ 漏掉 `整理备注` 章节（下游消费者无法判断 fetch 状态）
❌ 自创章节名（如 `## 背景`、`## 实验结果`）— 必须是 6 个固定章节

## 校验清单（每篇 paper.md 写完后）

- [ ] 6 个一级章节顺序正确
- [ ] 基本信息 8 个字段全有（可选字段可空）
- [ ] 关键数字至少 3 处加粗
- [ ] 摘要为英文原文，未翻译
- [ ] 末尾含 `fetch_status` 与 `fetch_source`
